# 定方向：做出看得到的方向，讓使用者用看的選

大多數人說不出自己要什麼配色或字體，但看到畫面時很清楚「這個不對」「這個可以，但綠色不好看」。所以視覺方向不靠問答決定，而是做出 2 到 3 個真的畫出來的方向，讓使用者挑、讓使用者指出喜歡和不喜歡的地方。

---

## 1. 設計命題（一句話）

從 PRODUCT.md 的使用者狀態與首要任務，濃縮出這個產品要帶給人的感覺，同時說出「平常」和「關鍵時刻」的樣子。

例：公司內部的模型平台，「像一間整理好的工具間：平常安靜、東西都在固定位置；要用的時候一伸手就拿得到，用完知道花了多少。」

## 2. 現實隱喻（4 到 6 個）

找現實世界中承擔同一種工作的系統或物件，借它的運作規律。每個寫三件事：它怎麼運作、可以借什麼、可能的風險。

規則：至少一個來自跟軟體無關的領域；不要只列「儀表板」這種同業的東西，那只會回到平均值。

## 3. 擲骰

```bash
python3 <skill>/scripts/roll.py 工具間 實驗紀錄本 機場塔台 --log design-review/roll.json
```

讓 AI 自己挑，它幾乎一定挑統計上最安全的選項。抽中的方向必須認真發展成主方向，不能一句「太大膽」就略過。

## 4. 做出 2 到 3 個方向

| 方向 | 怎麼來 |
|---|---|
| 主方向 | 骰子抽中的隱喻，認真發展 |
| 競爭方向 | 另一個你認為真的有競爭力的隱喻 |
| 對照組（可選） | 同類產品最常見的做法，讓使用者看見差別 |

**做法**
- 先找參考：照 `art-direction.md` 第十節，到 Awwwards 找 3 到 5 個同類型或同氣質的得獎作品，截圖並寫下借什麼。
- 每個方向先寫概念一句話，加上它在畫面上變成哪三件事（`art-direction.md` 第一節）。方向之間的概念要不同，不是同一個概念換顏色。
- 完成度要到可以拿去參賽：真的字體組合、看得見的格線、跟概念相關的影像或線稿、編排過的動態。不是線框、不是只有排版整齊的範本。
- 每個方向都是**真的 HTML 畫面**，不是情緒板、不是文字描述。用同一個關鍵畫面（通常是首要任務所在的那一頁）、同一份真實內容，差別才看得出來。
- 方向之間至少在三個面向有實質差異：版面結構、字體、色彩、密度、形狀與材質、導航方式。只換顏色不算不同方向。
- 每個方向都要先照 craft.md 的基本功做到位，再照 art-direction.md 做出它的個性；不要拿半成品和完成品比。
- 每個方向附三行說明：第一眼長什麼樣、為什麼適合（對應 PRODUCT.md 的哪個事實）、風險（可能讓誰看不懂、哪裡容易做過頭）。
- 用 `templates/compare.html` 放在同一頁切換比較，桌機和手機寬度都看得到。交付前確認每個方向都打得開。

**給使用者的問題**（只有這三題）
1. 哪一個方向最接近你要的？
2. 你喜歡的那個，有沒有哪裡不喜歡？（例如「款式可以，但綠色不好看」）
3. 其他方向裡，有沒有想借過來的部分？

使用者可以選一個、融合兩個，或要求重做。把回答原話記進 DESIGN.md 的「方向與依據」。

## 5. 調整指令

使用者看完說「再……一點」時，照下表轉成具體改法，不要整個重做：

| 使用者說 | 具體改法 |
|---|---|
| 再大膽一點 | 放大那個「大膽的一處」：加大主標或主視覺、強調色面積加大一處、版面不對稱更明顯 |
| 再安靜一點 | 拿掉裝飾、降低彩度、減少邊框與陰影、統一成一種強調方式 |
| 再精簡一點 | 刪掉次要資訊或收進展開區、合併重複的入口、減少字級種類 |
| 再專業一點 | 收斂配色、對齊更嚴格、數字等寬靠右、用詞更精確 |
| 再親切一點 | 圓角與留白加大、文字更口語、空狀態與提示更有人味 |
| 太擠或太空 | 調整區塊間距一階，不動元件本身 |
| 看不清楚 | 先檢查對比與字級，再看層次是否太多 |

## 6. DESIGN.md

寫在專案根目錄，是這個專案的視覺契約。之後每一頁都照它做；要改就在最下面記一筆版本與原因。

```markdown
# DESIGN.md（v1｜YYYY-MM-DD）

## 設計命題
<一句話>

## 方向與依據
<選定的方向、使用者的原話、從隱喻借了什麼、從其他方向融合了什麼>

## 色彩 token（每個都要有用途）
- --surface：<值>｜底色
- --ink：<值>｜主要文字；--ink-muted：<值>｜次要文字（對底色 ≥ 4.5：1）
- --accent：<值>｜只用在可操作元素與選取狀態
- 語意色：成功 <值>、警告 <值>、錯誤 <值>

## 字體與字級
- 中文：<字體>；西文與數字：<字體>
- 字級表：<例：13／15／18／22／28>；行高：內文 <值>、標題 <值>

## 間距與版面
- 基準：<例：8px>；常用：<8／16／24／32／64>
- 版面：<側欄寬、內容寬、格線>

## 元件規則
- 按鈕：主要（實心，每區最多一顆）、次要（外框）、文字連結
- 卡片：只用在可獨立操作的一組內容，不巢狀
- 標籤：只表示真實狀態，不能長得像按鈕
- 動效：只表達狀態改變；尊重 prefers-reduced-motion

## 大膽的一處
<這個產品唯一讓人記得的地方，以及它只出現在哪裡>

## 本專案禁用
- <從 antipatterns.md 挑出特別要防的，加上本專案特有的>

## 例外許可（要寫理由）
- <例：品牌漸層只用在 logo，理由：沿用既有品牌資產>

## 變更紀錄
- v1｜YYYY-MM-DD｜初版
```

## 已有設計系統時

專案已經有設計系統（公司元件庫、框架內建樣式）時，DESIGN.md 直接引用它，只寫補充規則與禁用清單；方向比較只在使用者要求改版時才做。

## 一次做完、使用者不在時

使用者要求直接做完時，仍然做出 2 到 3 個方向，選主方向繼續完成，其他方向保留在比較頁，交付時請使用者選；選了別的方向再改過去。
