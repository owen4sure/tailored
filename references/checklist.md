# 交付前檢查清單

每一項都要實際看過，不是憑印象打勾。做不到的項目寫「未驗證」並說明原因。

## 畫面

- [ ] 用真的瀏覽器在 1440、1024、768、390px 寬截圖（手機產品加 320、430px），每個寬度都沒有水平溢出、遮擋或跑版。
- [ ] 首屏三秒內看得出主角與主操作；一個區域只有一顆實心主按鈕。
- [ ] 長文字、長單號、長檔名能換行或完整查看，不靠縮小字體硬塞。
- [ ] 空狀態、載入中、錯誤、沒有權限，各自有明確的畫面。
- [ ] 比較頁（若有）每個方向都打得開、都能操作，不只是自己測過的那一個。

## 可讀與可操作

- [ ] 內文對比至少 4.5：1，大字至少 3：1；狀態不只靠顏色。
- [ ] 內文不小於 14px（手機 16px），任何文字不小於 12px。
- [ ] 觸控目標至少 44×44px（桌機主要操作至少 32px 高）。
- [ ] 用鍵盤可以走完核心任務，焦點框看得到。
- [ ] 開啟 `prefers-reduced-motion` 時沒有大幅動畫。
- [ ] 圖片有替代文字，只有圖示的按鈕有可讀名稱。

## 中文排版

- [ ] 台灣繁體中文、全形標點；沒有殘留的英文介面字、內部代號或簡體字。
- [ ] 沒有中文斜體、沒有拉寬字距；行高與行長在 craft.md 的範圍內。
- [ ] 同一件事全產品用同一個詞。

## 真實與完整

- [ ] 每個按鈕與連結都有真的目的地；沒做的功能不放入口。
- [ ] 沒有編造的數字、客戶、評價；示例資料有標示。
- [ ] 核心任務實際操作過一遍（點進去、完成、返回）；要接真實資料的，存一筆再讀回。
- [ ] AI 味掃描（scan.py）的每一筆命中都處理過：確認修掉，或寫明為什麼是誤報。

## 交付說明

- [ ] 分開寫：程式與靜態檢查結果、實際操作驗證了什麼、沒驗證什麼、使用者的視覺選擇是否已確認。
- [ ] 附上最後一回合的截圖與比較頁連結；使用者會打開的網址實際打開過。
