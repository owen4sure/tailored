# 正式系統：公司內部系統、後台、ERP、AI 平台

一句話：**工作系統的美感來自精準，不是表演。** 目標一樣是頂尖，但比的對象不同：不是 Awwwards 當日最佳的品牌網站，而是 Linear、Stripe、Mercury、Attio、Vercel 這類以介面細緻出名的產品。從 Awwwards 學的是細節的功力（`details.md`），不是表現手法。

同仁每天用八小時，要的是：一眼看懂、少點一下、不會出錯、看久了不累，而且用起來有被好好對待的感覺。

---

## 一、品牌網站的手法，哪些不能搬

| 不要搬過來 | 原因 | 改成 |
|---|---|---|
| 滿版大字、整頁換色 | 擠掉資料，每天看會膩 | 頁面標題 22 到 24px，一句話說明這頁做什麼 |
| 捲動觸發的動畫、視差、手卷 | 找資料時被打斷 | 內容一開始就在，只有因果才動 |
| 載入動畫、聲音、自訂游標、平滑捲動 | 拖慢、干擾操作 | 原生捲動與游標 |
| 每個區塊都換一種排法 | 每頁都要重新學 | 全系統同一套骨架 |

## 二、一樣要做到的

- 字級表嚴格（4 到 6 級），字距與行高精準，數字等寬靠右。
- 線條 1px 低透明，顏色極少，對齊到格線。
- 每個狀態都設計過：空、載入、錯誤、沒權限、被選取、停用、儲存中、已完成。
- 文字白話、具體，用同仁的說法。

## 三、個性放在哪裡

從使用者的工作世界，找一兩個「只有這裡才有」的細節，做到極致；其他地方安靜。

- 公文簽核的公司：台灣的日期章（上面單位、中間民國日期、下面姓名），核准時「蓋」下去。
- 管錢的頁面：帳冊的會計雙底線放在合計下、貨幣符號縮小變淡。
- 機房與模型平台：示波器般的即時細線、GPU 熱度條、串流回答的速度。
- 工地與工程：圖框的標題欄、圖號格式的單號。

說不出這個細節來自哪個真實世界，就是裝飾，不要放。

## 四、骨架與數字

**版面**
- 灰色畫布加一張白色主面板（深色系統用三階明度）；側欄 220 到 240px 直接放在畫布上，不另外加框。
- 頁首 48px，黏住、半透明加模糊，放麵包屑與這頁的主要動作。
- 內容最大寬 1120 到 1280px；表格可以用滿。

**字**
- 介面文字 13.5 到 14px；中文介面行高 1.5，段落 1.7。
- 頁面標題 22 到 24px、字重 600、字距 −0.012em；區塊標題 14.5px、600。
- 表頭 12.5px、500、第三層文字色；單號與代碼用等寬字 12px。

**表格與清單**
- 列高 44 到 46px（IBM Carbon：緊密 32、預設 40、寬鬆 48）；表頭跟著列高。
- 不畫直線（試算表類除外）；表頭黏住；整列滑過變色。
- 數字靠右、等寬；排序箭頭只出現在已排序的那一欄，其他欄滑過才出現。
- 多選後，底部浮出動作列：已選幾筆、合計多少、可以做什麼、取消選取。
- 未知的值寫「未填」或一個長橫線 `—`，不寫 N/A、null。

**狀態**
- 小圓點加文字；4 到 5 種語意色就夠。
- 「輪到我處理」的狀態，字重比其他狀態重一階。

**詳情頁**
- 左邊主內容：標題、說明、明細、流程、附件、動態與留言。
- 右邊黏住的屬性欄：標籤 76px 加值；窄螢幕改成標題下一行摘要。
- 上一張、下一張與「3 / 16」，讓人一張一張處理。

**表單**
- 新增與編輯從右側抽屜滑出，不跳頁。
- 標籤在上、說明在下，出錯時錯誤訊息取代說明，說原因與改法。
- 合計即時更新；送出鍵寫出動作與對象：「送出給主管」。

**首頁**
- 用一句話總結今天：「有 3 筆報支等你簽核，4 筆保證金這週到期。」不是一排四張 KPI 卡。
- 統計數字最多三個：上方一條細線、有比較基準、可以加真的走勢線。
- 接著是「等你處理」的清單，滑過出現核准、退回。

**動態**
- 120 到 200ms，`cubic-bezier(.2,.8,.2,1)`；只用在因果：蓋章、列被選取、抽屜進出、提示出現。
- 每天重複上百次的操作不加動畫。

**鍵盤與搜尋**
- ⌘K 搜尋與跳轉（單號、名稱、頁面、動作）；J、K 上下移動；Enter 打開；/ 聚焦搜尋；N 新增。
- 快捷鍵寫在提示框與清單底部，讓人自然學會。

## 五、不同系統，不同個性

工作系統也不能每個都長一樣。兩個示範的差別：

| | 北岬工作台（工程公司 ERP） | 玄武（地端模型平台） |
|---|---|---|
| 世界 | 公文、帳冊、印泥 | 機房、儀表、熱度 |
| 底色 | 暖灰畫布加白紙 | 石墨黑，三階明度 |
| 唯一的彩色 | 印泥朱紅，只出現在章上 | 熱度橘，只在過熱時出現 |
| 字 | Inter 加思源黑體，單號用等寬 | Geist 加思源黑體，數字用 Geist Mono |
| 招牌細節 | 日期章、會計雙底線、合計即時更新 | 示波器即時線、GPU 熱度條、串流速度與首字時間 |
| 動態 | 蓋章：放大、壓下、回彈 | 每秒更新的數字與線，新紀錄淡入 |

## 六、AI 在系統上最常犯的錯

| 常見做法 | 改成 |
|---|---|
| 每個區塊包圓角卡片加陰影 | 用線與留白分組 |
| 一排四張漸層 KPI 卡 | 一句話總結今天，加最多三個有比較基準的數字 |
| 側欄滿是彩色圖示方塊 | 單色線條圖示，16px，線寬 1.5，跟文字一樣重 |
| 表格數字置中、寬度不一 | 靠右、等寬，貨幣縮小變淡 |
| 「Welcome back 👋」、Emoji 當圖示 | 依時間問候，加一句今天的重點 |
| 狀態只用顏色 | 圓點加文字 |
| 每顆按鈕都是實心主色 | 一個區域只有一顆實心 |
| 每張統計卡配一樣的假走勢線 | 用真資料，沒有就不放 |
| 深色加青紫發光、半透明玻璃卡 | 三階明度的石墨色，彩色只留給狀態 |

## 七、參考誰、學什麼

產品介面大多要登入才看得到，所以從這些地方研究：官網上的真實介面畫面、公開的示範站、設計系統文件、Awwwards 的 UI design、Microinteractions、Data Visualization、Forms and Input 標籤。一樣用無頭瀏覽器放大兩倍截圖，裁出局部比對。

| 參考 | 學什麼 |
|---|---|
| Linear | 深色的層次、密度、鍵盤操作、圖示與文字的重量平衡 |
| Stripe 後台 | 表格、狀態、金額格式 |
| Mercury | 金額的小數縮小、極淡的分隔線、讓人信任的整體感 |
| Attio | 資料密度、淡底加同色框的標籤、用 logo 與頭像幫助辨識 |
| Tailwind Catalyst（公開示範站） | 畫布加主面板、側欄目前位置、統計數字上方的線 |
| Vercel Geist 與 Web Interface Guidelines | 表格內容規則（未知值、相對時間、等寬數字）與大量互動細節 |
| IBM Carbon | 表格密度、批次動作列、排序規則 |
| SmartHR、freee | 日文商務系統的字級、行高、數字靠右，中文系統可以直接借 |
| SAP Fiori | 反例參考：功能完整但顯得老派的企業介面長什麼樣 |
