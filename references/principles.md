# 四個設計原則：檢查問題、評分錨點、改法

好設計一句話：**把使用者的認知成本降到最低，一眼抓到重點，每次操作都符合預期。**
拆開就是下面四個原則。審查第一層用它們打分，修正時用它們決定怎麼改。

設計有主觀成分，所以這裡只檢查「有沒有違反原則」，不判斷「好不好看」。

---

## 評分錨點（四原則共用）

| 分數 | 意思 |
|---|---|
| 0 | 嚴重違反：多處違反，而且直接妨礙首要任務 |
| 1 | 明顯違反：至少一處會誤導或干擾使用者 |
| 2 | 大致符合：只剩不影響理解與操作的小瑕疵 |
| 3 | 完全符合：找不到違反之處，而且畫面上有看得到的正面證據 |

閘門要求每項至少 2 分。給 3 分要寫出正面證據，給 0 或 1 分要對應到至少一個 finding。

---

## 一、符合預期

**定義**：長得像什麼，就要能做什麼；能做什麼，就要長得像什麼。使用者看外觀就知道怎麼用，照直覺操作就會成功。

**為什麼**：每一次「以為能點結果不能點」或「找不到能點的地方」，都在消耗使用者的信任。假的互動比沒有互動更糟，因為它會教使用者不要相信這個畫面。

**檢查問題**
1. 看起來能點的（膠囊、帶框小標、手指游標、底線字），真的都能點嗎？
2. 能點的（連結、按鈕），看起來都像能點嗎？段落中的連結跟內文分得出來嗎？
3. 狀態指示（燈號、Live、即時數字、進度條）背後有真實狀態嗎？
4. 每個按鈕與連結都有真的目的地嗎？（`href="#"` 不算）
5. 同一種樣式在整頁代表同一種意思嗎？（例如藍字一律是連結）
6. 手機上點得到嗎？（觸控目標至少 24×24px，主要操作建議 44px 以上）

**常見違反與改法**

| 違反 | 改法 |
|---|---|
| 標題上方的裝飾膠囊（A1） | 優先刪除。內容真的重要，就改成沒有框、沒有底色、沒有圓角的普通小字；或者真的做成連結，指向說明頁 |
| 會閃的綠點與「All systems operational」（A2） | 沒有真實狀態就刪除。有的話接上真資料，並讓狀態改變時外觀跟著改變 |
| `href="#"` 的按鈕（A3） | 接上真的目的地；還沒有目的地的功能就先不要放按鈕 |
| 段落連結看不出來（A4） | 加底線，或用跟內文明顯不同的顏色 |
| div 加 `cursor:pointer` 當按鈕（A5） | 改用 `<button>` 或 `<a>`；不能點的元素移除手指游標 |

## 二、主次分明

**定義**：一頁只有一個主角。最重要的東西最大、最顯眼，其他元素都要退讓。三秒內要看得出這頁想說什麼、該按哪裡。

**為什麼**：重要程度不同的東西長得一樣，使用者就得自己去比較。大部分人不會比較，會直接離開。

**檢查問題**
1. 三秒測試：看首屏三秒，說得出這頁最想傳達的一件事嗎？說得出該按哪裡嗎？
2. 首屏的實心主按鈕是不是只有一顆？其他行動是不是降成次要樣式或文字連結？
3. 標題與內文的字級差距夠大嗎？（建議首屏最大字至少是內文的 1.8 倍以上）
4. 功能介紹裡，最重要的那一項是不是佔最大面積？
5. 瞇眼測試：把截圖模糊之後，還看得出結構與重點嗎？
6. 文字讀得清楚嗎？（內文對比至少 4.5：1，大字 3：1，任何文字都不小於 12px）

**常見違反與改法**

| 違反 | 改法 |
|---|---|
| 三張等大的「圖示＋標題＋說明」卡（B1） | 挑出產品最強的那一項，給它大區塊，最好是真實畫面或機制演示；其餘降級成清單 |
| 首屏三顆實心按鈕（B2） | 保留一顆主要行動，其餘改成外框按鈕或文字連結 |
| 字級階層扁平或字級太多（B3） | 收斂成 4 到 6 級的字級表，標題與內文拉開比例 |
| 首屏塞滿小字（B4） | 首屏只留主標、一句說明、一個行動、一個證據；其他往下移 |
| 灰字對比不足（E1） | 調深文字或調整底色，直到過 4.5：1；裝飾性小灰字乾脆刪掉 |

## 三、克制

**定義**：只留下真正必要的東西。每一條邊框、每一個顏色、每一段動效都要說得出存在的理由。好設計的極致是看還能拿掉多少，而不是看還能加多少。

**為什麼**：每多一個沒有用的裝飾，就分走一點注意力。AI 做的畫面最常見的問題，就是到處發光、到處套框；把這些全部拿掉，資訊其實一樣都沒少。

**檢查問題**
1. 刪除測試：把這個元素拿掉，使用者會少知道什麼嗎？答不出來就刪。
2. 顏色有功能意義嗎？強調色是不是只有一個（加上成功、警告、錯誤這類語意色）？
3. 卡片是不是只用在「可以獨立操作的一組內容」？有沒有卡片套卡片？
4. 動效是不是只用來表達狀態改變或因果關係？有沒有無限循環的裝飾動畫？
5. 漸層、光暈、玻璃擬態、模糊色塊，都說得出理由嗎？

**常見違反與改法**

| 違反 | 改法 |
|---|---|
| 漸層文字（C1） | 改成單色；要強調就靠字級與粗細 |
| 紫藍漸層、彩色光暈、模糊光斑（C2、C4） | 刪除，改用單一底色；需要層次就用細微的明度差 |
| 彩色發光陰影（C3） | 刪除，或改成很淡的中性陰影，只用在真的浮在上層的元素 |
| 卡片套卡片、到處都是框（C5） | 外層拿掉框，用留白與對齊分組；內層只在需要時保留 |
| Emoji 當功能圖示（C9） | 刪除；需要圖像就用產品的真實畫面或一致的線條圖示組 |
| 強調色過多（C12） | 收斂成一個主色（只給可操作元素）加語意色 |

## 四、量身打造

**定義**：這個設計是為了這個產品、這群使用者、這個使用情境做的。動手前要先搞清楚三件事：這是什麼、給誰用、在什麼情境下用。

**為什麼**：藥袋字大樸素，是因為生病的人要看清楚怎麼吃；洋芋片包裝花俏，是因為要在貨架上搶眼球。網頁也一樣。焦慮的病人點進醫療網站，要的是急診電話，不是旋轉的 3D 模型。

**檢查問題**
1. 換名測試：把產品名換成同類競品，首屏和主要功能區是不是幾乎不用改就成立？成立就不及格。
2. 首要任務的入口，是不是對準使用者當下最迫切的需求？（對照 PRODUCT.md）
3. 視覺語氣符合使用者當下的心理狀態嗎？（焦慮、趕時間、好奇、比價）
4. 畫面上有沒有展示產品實際怎麼運作（真實畫面、機制演示），還是只有抽象插圖與圖示？
5. 文案具體嗎？數字有出處嗎？（只能用 PRODUCT.md「可證實的數據」裡列的）

**常見違反與改法**

| 違反 | 改法 |
|---|---|
| 沒有出處的數據與背書（D1） | 刪除；有真實數據就照 PRODUCT.md 寫並附出處；需要佔位就標「［待補：真實數據］」 |
| 通用行銷詞（D2） | 改寫成這個產品才說得出的具體句子：誰、在什麼情況、得到什麼 |
| 換名也成立的標題（D3） | 標題寫出產品的獨特機制或使用情境 |
| 抽象插圖取代產品畫面（D4） | 換成真實畫面，或用 HTML 做出機制演示 |
| 風格不符情境（D5） | 回到 PRODUCT.md 的使用者狀態，重新決定語氣；必要時回到步驟 2 重定方向 |
